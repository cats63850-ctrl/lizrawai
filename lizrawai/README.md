# Markov Bot — свой аналог GenAi

Discord-бот, который учится на сообщениях сервера и собирает из них новые
через цепи Маркова. Никаких API-ключей и оплаты токенов: весь «интеллект» —
это статистика по тому, что писали в чате.

Одна обязательная зависимость — `discord.py`. База на SQLite из стандартной
библиотеки.

## Что умеет

| Команда | Что делает | Права |
|---|---|---|
| `g.generate [слово]` | Сгенерировать сообщение, при желании с затравки | все |
| `g.dialog [2-8]` | Несколько реплик подряд | все |
| `g.stats` | Сколько накоплено и как настроено | все |
| `g.import [сколько] [#канал]` | Затянуть историю канала в корпус | Управление сервером |
| `g.minwords <1-10>` | Минимум слов в сообщении, чтобы оно училось | Управление сервером |
| `g.config` | Показать настройки сервера | все |
| `g.wizard` | Мастер настройки с кнопками | Управление сервером |
| `g.read on\|off` | Разрешить/запретить сбор сообщений | Управление сервером |
| `g.autogen on\|off` | Писать самому без команды | Управление сервером |
| `g.interval <n>` | Раз во сколько сообщений писать | Управление сервером |
| `g.filters mentions\|links\|emoji on\|off` | Что вырезать из корпуса | Управление сервером |
| `g.order <1-4>` | Порядок цепи | Управление сервером |
| `g.prefix <новый>` | Сменить префикс | Управление сервером |
| `g.ignore` / `g.unignore` | Исключить канал из сбора | Управление сервером |
| `g.wipe [подстрока]` | Стереть корпус, с подтверждением | Управление сервером |
| `g.fakemute @кто [10м] [причина]` | Сделать вид, что выдан тайм-аут | Тайм-аут участников |
| `g.fakeban @кто [причина]` | Сделать вид, что участник забанен | Банить участников |
| `g.optout` / `g.optin` | Не собирать лично мои сообщения | все |
| `g.forgetme` | Удалить мои сообщения из корпуса | все |
| `g.requestdata` | Прислать в ЛС всё, что собрано про меня | все |

Все команды работают и как слэш-команды (`/generate`), и по префиксу.
Упоминание бота тоже считается префиксом: `@Бот generate` сработает, даже
если префикс на сервере поменяли и все о нём забыли.

## Установка на VPS в одну команду

```bash
curl -fsSL https://raw.githubusercontent.com/cats63850-ctrl/lizrawai/main/install.sh | sudo bash
```

Скрипт сам поставит зависимости, заведёт отдельного пользователя, создаст
venv, спросит токен и настроит автозапуск через systemd. После установки бот
поднимается при загрузке сервера и переживает обрыв связи с Discord.

Запусти ту же команду ещё раз, чтобы **обновить** бота: код подтянется
заново, а токен и накопленный корпус останутся на месте.

```bash
journalctl -u markovbot -f        # логи
systemctl restart markovbot       # рестарт
sudo bash install.sh --uninstall  # снять автозапуск
```

## Запуск вручную

Нужен Python 3.10 или новее.

```bash
python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env           # и вписать туда токен
python bot.py
```

Venv тут не для красоты: на Arch, Fedora, Debian и всём, где действует
PEP 668, глобальный `pip install` откажется работать с ошибкой
`externally-managed-environment`. Внутри venv всё ставится нормально.

В консоли должно появиться `Вошли как ...` — значит бот в сети. Пока
живёт процесс, живёт и бот; закрыл терминал — бот ушёл в офлайн.
Чтобы этого не происходило, смотри раздел про автозапуск ниже.

### Где взять токен

1. [Discord Developer Portal](https://discord.com/developers/applications) → **New Application**.
2. Вкладка **Bot** → **Reset Token** → скопировать в `.env`.
3. Там же, в **Privileged Gateway Intents**, включить **MESSAGE CONTENT INTENT**.
   Без него бот не увидит текст сообщений — ровно та ошибка, из-за которой
   боты отвечают «I can't read messages here».
4. Вкладка **OAuth2 → URL Generator**: отметить скоупы `bot` и
   `applications.commands`, из прав — `Send Messages`, `Read Message History`,
   `View Channels`. Открыть получившуюся ссылку и пригласить бота.

### Первая настройка на сервере

```
g.wizard          # включить чтение кнопкой
g.import 5000     # затянуть историю канала, чтобы не ждать неделями
g.generate        # проверить
g.autogen on      # если хочется, чтобы бот вставлял реплики сам
g.interval 30
```

`g.import` — самое важное на старте. Живой сбор наполняется медленно, а
для внятной генерации нужны тысячи сообщений; импорт даёт их сразу.
Команда идёт по одному каналу за раз, другой указывается явно:
`g.import 5000 #флудилка`. Гонять её повторно безопасно — сообщения
различаются по ID Discord, дубли в корпус не попадают.

Сообщения короче двух слов не учатся: из «да» и «лол» переходов не
построить. Порог меняется через `g.minwords`.

## Автозапуск через systemd

Чтобы бот не умирал вместе с терминалом и сам поднимался после
перезагрузки, в папке `deploy/` лежат два готовых юнита.

**Своя машина или VPS под своим юзером** — `deploy/markovbot.service`:

```bash
mkdir -p ~/.config/systemd/user
cp deploy/markovbot.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now markovbot
loginctl enable-linger $USER      # работать и без активного логина

journalctl --user -u markovbot -f  # логи
```

**VPS с отдельным пользователем** — `deploy/markovbot-system.service`,
инструкция по установке в комментариях внутри файла.

Юнит рассчитан на проект в `~/markovbot` и venv в `~/markovbot/.venv` —
если разложил иначе, поправь `WorkingDirectory` и `ExecStart`.
`Restart=always` вернёт бота в строй, если Discord оборвёт соединение
или процесс упадёт.

## Как это работает

Каждое сообщение чистится фильтрами (`filters.py`) и складывается в SQLite
(`storage.py`). Из корпуса собирается цепь Маркова (`markov.py`): для каждой
пары соседних слов запоминается, какие слова шли следом и сколько раз.
Генерация — случайное блуждание по этой статистике.

Модель живёт в памяти и дообучается на лету, из базы она пересобирается
только при старте, смене порядка цепи или после `wipe`.

### Про порядок цепи

`order` — сколько предыдущих слов учитывается при выборе следующего.

* **1** — максимальный бред, слова стыкуются как попало. Смешно, но бессвязно.
* **2** — по умолчанию. Фразы звучат почти осмысленно, но склеены из разных сообщений.
* **3–4** — на маленьком корпусе бот начнёт дословно цитировать людей,
  потому что вариантов продолжения просто не остаётся. Имеет смысл только
  на десятках тысяч сообщений.

Посмотреть разницу можно без Discord:

```bash
python demo.py
```

## Приватность

Сделано так, чтобы бот не превратился в проблему:

* Сбор сообщений **выключен по умолчанию** — до `g.read on` в базу не попадает ничего.
* `@everyone` и `@here` не учатся никогда и ломаются в выводе, плюс на уровне
  бота стоит `AllowedMentions.none()` — пингануть кого-то он не может физически.
* Приглашения на серверы вырезаются всегда.
* Ссылки и упоминания вырезаются по умолчанию, отключается через `g.filters`.
* Любой человек может выйти из сбора (`g.optout`), удалить свои сообщения
  (`g.forgetme`) и забрать их копию (`g.requestdata`).
* Команды в корпус не попадают, чтобы бот не учился на самом себе.

## Файлы

```
bot.py              точка входа, кэш моделей, обработка ошибок
config.py           чтение .env
markov.py           цепи Маркова, без зависимостей от Discord
filters.py          чистка текста до обучения и перед отправкой
storage.py          SQLite: корпус, настройки, приватность
cogs/listener.py    сбор сообщений и автогенерация
cogs/generation.py  generate, dialog, stats
cogs/settings.py    конфиг, мастер, удаление данных
cogs/importer.py    импорт истории канала
cogs/prank.py       шуточные fakemute и fakeban
demo.py             генерация в консоли, без токена
install.sh          установка и обновление на VPS одной командой
deploy/             systemd-юниты для автозапуска
tests/              тесты
```

## Что можно докрутить

* Мемы-картинки поверх сгенерированного текста — демотиваторы и impact-шрифт
  через Pillow.
* Генерация «в стиле конкретного человека»: фильтровать корпус по `author_id`,
  колонка уже есть.
* Импорт сразу по всем каналам сервера одной командой.
* Хранить саму цепь в базе вместо пересборки из корпуса — если сервер
  большой и старт станет медленным.
